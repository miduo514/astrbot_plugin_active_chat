# 群聊主动消息（astrbot_plugin_active_chat）

按**群聊独立计时**的主动消息插件：某个群连续静默达到阈值后，AstrBot 会按递增概率判定是否主动发一条消息；可选地，还能截取电脑屏幕、让 LLM 看懂画面后生成一条与屏幕内容相关的消息。

- 插件名：`astrbot_plugin_active_chat`
- 适用版本：AstrBot `>= 4.5.7`（Python 3.10+）
- 依赖：`mss`（可选，用于截屏；缺失时截屏分支自动降级）

---

## 功能特性

- **每个群独立状态**：独立计时器、独立候选态、独立连续失败计数 B，互不影响。
- **静默触发**：群内 X 分钟没有新消息才进入候选；候选期内只要来一条消息，立即重置计时。
- **递增概率**：进入候选后每隔 Y~Z 分钟随机判定一次，实际概率 = `min(1, A + B × C)`，失败累加、成功清零。
- **普通主动消息**：注入当前会话人格 system prompt，追加可配置的额外提示词，可选注入对话历史。
- **截屏主动消息**（默认关闭）：按概率 P 走截屏分支——截屏 → LLM 理解 → 生成文案 → 发文字 → 等 1 秒 → 发图；任何环节失败都自动回退为普通主动消息，不会重复掷 P。
- **分段回复**：发送遵循 AstrBot 全局 `platform_settings.segmented_reply` 配置，行为与官方一致。
- **管理指令**：查看状态、手动触发，均限制管理员可用。
- **全程可观测**：日志明确标注群聊 UMO、第几次判定、当前概率、成功/失败。

## 安装

1. 将整个 `astrbot_plugin_active_chat` 目录放入 AstrBot 的 `data/plugins/` 下。
2. 安装依赖（截屏功能需要）：

   ```bash
   pip install -r requirements.txt
   ```

   也可以在 WebUI 插件详情中点击安装依赖。
3. 打开 AstrBot WebUI → 插件管理 → 重载该插件。
4. 在插件配置里填写 `group_umos`：在目标群发送 `/sid`，**原样复制**返回的完整 UMO。
5. 重载插件后发送 `/主动消息状态`，确认每个群都显示「候选：否」且没有「⚠ 平台不可用」。

> **关于 UMO（会话标识）**：格式为 `<平台实例ID>:<消息类型>:<会话ID>`，例如
> `default:GroupMessage:1098672459`。第一段是 WebUI 里平台配置的**实例 ID**，
> 不是适配器类型 —— 写成 `aiocqhttp:GroupMessage:...` 时 AstrBot 会报
> `cannot find platform for session ...` 并静默丢弃消息。
> 插件会自动把适配器类型纠正为唯一平台实例，并可从群消息中学习真实 UMO；
> 但只要条件允许，仍建议按 `/sid` 原样填写。
> 实在不确定时，发一条群消息后看 `/主动消息状态` 末尾的「最近收到消息的会话」，
> 直接复制那里的值即可。

> 插件目录结构不会被修改；运行期数据（状态文件、截图）保存在
> `data/plugin_data/astrbot_plugin_active_chat/`，升级/重装插件不会丢失。

## 配置项

| 配置键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `group_umos` | list | `[]` | 需要监控的群聊 UMO 列表，例如 `["default:GroupMessage:123456789"]`（第一段必须是平台实例 ID，用 `/sid` 原样复制） |
| `silence_minutes` | int | `10` | 静默阈值 X，范围 1~120 分钟 |
| `check_interval_min` | int | `5` | 判定间隔下限 Y，范围 1~60 分钟 |
| `check_interval_max` | int | `10` | 判定间隔上限 Z，范围 1~60 分钟（小于 Y 会自动交换） |
| `base_probability` | float | `0.1` | 初始判定概率 A，范围 0~1 |
| `failure_increment` | float | `0.1` | 失败增加概率 C，范围 0~1 |
| `normal_extra_prompt` | text | 空 | 普通主动消息额外提示词，追加在人格提示词之后 |
| `inject_history` | bool | `true` | 是否注入当前 LLM 对话历史 |
| `enable_screenshot` | bool | `false` | 截屏主动消息总开关 |
| `screenshot_probability` | float | `0.5` | 判定成功时走截屏分支的概率 P |
| `screenshot_extra_prompt` | text | 空 | 截屏主动消息额外提示词，追加在人格提示词之后 |

超出范围的数值不会被拒绝加载，而是**自动收敛到边界并打印一条 WARN 日志**，避免配置写错导致插件不可用。

## 管理指令

| 指令 | 别名 | 说明 |
|---|---|---|
| `/主动消息状态` | `/active_status` | 列出每个群的 UMO、静默时长、是否候选、已判定次数、B、当前概率、距下次判定时间 |
| `/主动消息测试 <序号或UMO>` | `/active_test` | 忽略计时器与概率，立即在目标群触发一次主动消息；仍按 P 决定是否走截屏分支，并回报结果 |

两个指令限制为管理员可用。
`/主动消息测试` 支持「序号」（如 `1`）或 UMO 精确/唯一模糊匹配，且只允许操作配置内的群。

状态输出示例：

```
【主动消息状态】共 2 个群
阈值 X=10m ｜ 判定间隔 5~10m ｜ A=0.10 ｜ C=0.10 ｜ 历史注入=开
截屏=关闭（P=0.50，组件可用）

1) aiocqhttp:GroupMessage:123456789
   静默 12m34s（阈值 10m） ｜ 累计触发 7 次
   候选：是（已判定 3 次）｜ 下次判定：4m05s后
   B=2 ｜ 当前概率 0.30
```

## 工作机制

```
群消息 ──► 刷新 last_activity、退出候选、唤醒任务
                 │
                 ▼
        等待「静默 X 分钟」
                 │ 到期（且无新消息）
                 ▼
        进入候选 ── 随机等待 Y~Z 分钟 ──► 判定：random() < min(1, A + B×C)
                 ▲                              │
                 │ 失败：B += 1                  │ 成功
                 └──────────────────────────────┤
                                                ▼
                        按 P 决定分支 ──► 截屏主动消息（失败则回退）／普通主动消息
                                                │
                                                ▼
                                    发送成功 → B 清零，重新开始静默计时
```

关键行为约定：

- **收到新消息**：重置静默计时，并清零本轮 B（视为新的静默周期）。
- **发送失败**：不算成功，B 累加，退避 30 秒后继续候选，避免平台断线时高频重试。
- **主动消息本身**也视为一次「新消息」，发送成功后会重置静默计时，不会连续触发。
- **重启后**：计时器与 B 归零，只保留累计触发次数等统计，避免停机一夜后一启动就按高概率连发。
- **UMO 自动校正**：配置的平台标识若与真实 UMO 不一致，插件会按平台实例自动纠正、并按「消息类型:会话ID」从群消息中学习真实 UMO；发送前还会校验平台是否可达，不可达时明确报错而不是假装发送成功。

## 截屏主动消息

> ⚠️ **截屏功能依赖于桌面环境，无头服务器请勿开启截屏。**
>
> 无桌面会话、远程无头登录、锁屏状态下，截屏会失败或得到全黑画面；
> 插件会自动回退为普通主动消息，但请不要在无头环境中依赖该功能。

- 优先使用 `mss` 抓取**主显示器**；`mss` 不可用时尝试 Pillow 的 `ImageGrab`；两者都缺失则截屏分支永远回退普通消息（并在日志中提示一次）。
- 抓到全黑帧（锁屏/无桌面）会被判定为失败并回退，不会把黑图发给群。
- 截图临时文件保存在 `data/plugin_data/astrbot_plugin_active_chat/screenshots/`，只保留最近 20 张。
- 画面理解与文案生成分两步：先由视觉模型客观描述屏幕内容，再结合人格与额外提示词生成消息；视觉调用失败同样回退普通消息。
- **隐私提醒**：截屏会包含屏幕上的一切可见内容（聊天窗口、文档、通知等）。启用前请确认该机器与群聊场景可以接受这一风险。

## 日志与排错

日志统一带 `[active_chat][<UMO>]` 前缀，例如：

```
[active_chat][aiocqhttp:GroupMessage:123] 静默 10 分钟达成，进入候选状态
[active_chat][aiocqhttp:GroupMessage:123] 第 3 次判定 | p=0.300（A=0.10 + B=2 × C=0.10） | roll=0.612 | 失败
[active_chat][aiocqhttp:GroupMessage:123] 第 4 次判定 | p=0.400（A=0.10 + B=3 × C=0.10） | roll=0.113 | 成功
[active_chat][aiocqhttp:GroupMessage:123] 主动消息已发送 source=auto branch=normal chars=42 elapsed=3.2s persona=default
```

常见问题：

| 现象 | 排查方向 |
|---|---|
| 一直不触发 | `group_umos` 是否填写正确（用 `/sid` 核对）；`/主动消息状态` 里的「距进入候选」是否在倒数；A 是否被设为 0 |
| 触发过于频繁 | 调大 X 或减小 A / C；确认没有多个群共用同一个 UMO |
| 截屏从不生效 | `enable_screenshot` 是否为 true；`pip show mss` 是否安装；日志中是否有「截屏失败」「全黑」告警 |
| 报「未找到可用的 LLM Provider」 | 在 AstrBot 中配置默认对话模型，或在 WebUI 中检查 Provider 设置 |
| 消息没有分段 | 检查 AstrBot 全局配置 `platform_settings.segmented_reply.enable` 与 `words_count_threshold` |
| 群里没人说话却立刻触发 | 检查是否有其他机器人/定时任务在群里发消息（任何新消息都会重置计时） |
| 日志出现 `cannot find platform for session` | UMO 第一段写成了适配器类型（如 `aiocqhttp`）。插件会自动纠正并在日志提示；若仍失败，按 `/主动消息状态` 里「最近收到消息的会话」原样复制 UMO |
| 状态里显示「⚠ 平台不可用」 | 当前 UMO 无法对应到任何平台实例，先发一条群消息让插件学习真实 UMO，再复制状态里列出的值 |

## 目录结构

```
astrbot_plugin_active_chat/
├── main.py                  # 插件入口：指令、消息监听、生命周期
├── metadata.yaml            # 插件元信息
├── _conf_schema.json        # 配置定义（WebUI 可视化）
├── requirements.txt         # 依赖（mss）
├── README.md
└── core/
    ├── models.py            # 配置快照、单群状态、执行结果
    ├── manager.py           # 状态表、监督循环、指令支撑
    ├── worker.py            # 单群状态机（静默 → 候选 → 判定 → 发送）
    ├── compat.py            # AstrBot API 适配层（LLM/人格/历史/分段/发送）
    ├── llm.py               # 提示词组装与文案清洗
    ├── screenshot.py        # 截屏、全黑帧检测、文件清理
    ├── sender.py            # 分段回复拆分与发送
    ├── store.py             # state.json 原子读写
    └── logutil.py           # 统一异常日志
```

## 已知限制

- 只处理 `group_umos` 中列出的会话；私聊与其他群完全忽略（不注册全局回复，不会影响正常聊天）。
- 分段回复复刻了官方配置语义；若运行版本的官方实现细节有出入，以全局配置的实际效果为准。
- 截屏固定抓取主显示器，暂不支持多屏拼接或指定窗口。
- 运行期计时与 B 不跨重启恢复（设计如此），`state.json` 仅保存观测数据。
